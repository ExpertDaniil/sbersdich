# Audit playbook

Цель: найти подтверждаемую уязвимость и создать требуемый отчёт, не меняя код
проекта.

1. Прочитать instruction и локальный `AGENTS.md`; зафиксировать точный путь и
   схему deliverable.
2. До любых действий снять validation baseline вне `/app` и `git status`. Не
   выполнять write/patch-команды над приложением.
3. Найти входные границы: HTTP-параметры, body-модели, CLI, файлы и переменные
   окружения.
4. Проследить данные до опасных sink: SQL, shell, path, template, deserialization,
   auth и secrets.
5. Для Python/PostgreSQL сначала запустить ограниченный AST scanner. Каждый
   результат подтвердить чтением конкретного source range; отсутствие результата
   не считать доказательством безопасности.
6. Отделить динамические значения от допустимой динамической структуры. SQL
   placeholders защищают значения, но не имена таблиц или колонок.
7. Записать только findings с доказуемой цепочкой `source → transform → sink`.
8. Запустить общий validator в режиме `audit`, передав baseline и обязательный
   `security-report`. Он должен разрешить только создание deliverable.
9. Повторно проверить `git status`: исходники приложения не должны измениться.

Для audit-отчёта использовать поля из инструкции без переименования. Не читать
`solution`, verifier output или expected-файлы.

Для каждого finding проверить достижимость цепочки при фактических ограничениях
в коде, включая преобразования и действия вызываемой библиотеки (например,
автоматический переход по redirect после первоначальной проверки URL).
Не заявлять обход allowlist без объяснения, как вход проходит конкретное условие.
`location` — строка с исходным путём и диапазоном строк, а не объект или алиас Fxxx.
Схема отчёта задаётся artifact_rules; собственный файл отчёта не является схемой.
