# CTF playbook

Цель: получить флаг из локальных артефактов, записать его строго в путь из
instruction и не изменить файлы задания.

1. Зафиксировать точный output path и требуемый формат. Если путь явно не
   указан, не угадывать имя файла и не завершать задачу успешно.
2. Сделать ограниченный inventory через `list_files`. Не читать `solution`,
   `expected`, `tests` или verifier-данные и не обращаться в интернет.
3. Сначала искать явные clues и маркеры через `search_text`. Текст читать
   небольшими диапазонами `read_file`, бинарные данные — `read_bytes`.
4. Сформулировать проверяемую цепочку преобразований. Для base32/base64,
   base64url, hex, URL encoding, ROT13, reverse, repeating XOR, gzip и zlib
   использовать `ctf_transform`; не декодировать на глаз.
   Для бинарного файла передать `path`, нулевое `offset`, точное `length` и
   `steps`: инструмент сам прочитает диапазон. Не переписывать hex из вывода
   модели. Разворот байтов — `reverse_bytes`; `reverse` разворачивает UTF-8
   символы. Текстовый hex требует первого шага `hex`. У XOR ключ задаётся
   через `key_text` либо `key_hex`, не через `key`.
   При ошибке распаковки сначала проверить magic, endian, начало payload и
   объявленную длину. Не менять заданный порядок восстановления без новых
   доказательств. Сверить возвращённые `input_size_bytes` и `input_sha256`.
5. Не перебирать неограниченные пространства ключей. XOR применять только при
   наличии ключа или доказуемой короткой гипотезы из локальных данных.
6. Проверить полученный текст: формат флага, полную длину, отсутствие
   обрезания и соответствие clues. Совпадение только с похожим словом не
   считать доказательством.
7. Записать только финальное значение через `write_exact_text` в путь из
   контракта. Не добавлять Markdown, пояснения и перевод строки, если этого нет
   в требовании.
8. Перечитать output и вызвать `finish`. Validator должен подтвердить, что
   создан только заявленный артефакт, а исходные challenge-файлы не изменены.

При повреждённых данных, неоднозначном результате или отсутствии output path
продолжить исследование либо завершить с явной ошибкой — флаг не придумывать.

Перед бинарным carving прочитать описание формата и metadata. `binary_records`
принимает magic_hex, явный endian header_format и length_field (индекс поля длины).
Он возвращает точные payload_offset/payload_length и header_values для всех
кандидатов. Выбрать требуемый metadata тип; передать найденный диапазон в
ctf_transform и выполнить операции в порядке, заданном описанием формата.
