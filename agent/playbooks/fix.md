# Fix playbook

Цель: минимально устранить корневую причину уязвимости и сохранить штатное
поведение проекта.

1. Прочитать instruction, `AGENTS.md`, manifest зависимостей и доступные тесты.
2. Снять validation baseline вне `/app`: состояние файлов, `git status`,
   релевантные тесты и точный уязвимый data flow.
3. Выбрать наименьшее исправление на уровне sink. Для SQL передавать команду и
   untrusted values драйверу раздельно; не применять escaping как основную защиту.
4. Автоматический parameterizer разрешён только для поддерживаемого asyncpg
   f-string value context. Имена таблиц, колонок и смешанные templates передаются
   LLM для ручного минимального patch.
5. После изменения выполнить по порядку:
   - повторный security scan;
   - `py_compile` или аналог синтаксической проверки;
   - узкие security-тесты с положительным и отрицательным сценарием;
   - штатную project test suite из инструкции;
   - общий validator в режиме `fix`: syntax, команды, защищённые пути, diff и
     отсутствие изменений dependency manifests.
6. При падении теста определить причину, а не менять тест ради зелёного результата.
7. Остановиться после доказанного исправления; не проводить несвязанный refactor.

Явные `security_requirements` из instruction проверяются отдельным post-edit
guard. Для containment не использовать строковый `startswith`: sibling path с
общим префиксом не является дочерним. Для одноразового секрета хранить digest,
а не raw token даже в ключе mapping. Если контракт требует reject structured
credentials, тип отклоняется исключением до построения database query, а не
тихим `None`. Request mapping сначала проецируется через allowlist. Webhook HMAC
сравнивается constant-time и связывает timestamp с точными raw body bytes.

При `finish` оба runtime автоматически запускают project pytest-команды,
зафиксированные из instruction и корневого `AGENTS.md` до редактирования кода.
Если явной команды нет, но есть Python-тесты в `tests/`, запускается эта папка.
Используется Python из локальной `.venv`, если он существует, иначе Python агента.
Не устанавливать pytest или зависимости во время задачи: отсутствие runner,
ошибка теста, отсутствие собранных тестов и timeout блокируют завершение.
Вывод проверки возвращается в validation feedback; устранить причину и повторить
`finish`. Успешный `run_check` или Candidate Arena не заменяет эту финальную проверку.
Тесты, `AGENTS.md`, `pytest.ini`, `conftest.py` и dependency manifests менять нельзя.
Автоматический runner C15 поддерживает pytest; отсутствие поддерживаемой suite
отмечается в отчёте и не означает прохождение скрытых тестов организаторов.

Не читать `solution`, verifier output или expected-файлы. Перед завершением
убедиться, что требуемые артефакты созданы, а запрещённые файлы не изменены.

Для идентификаторов SQL и направлений сортировки placeholders не подходят.
Использовать конечный allowlist/отображение, нормализовать регистр согласно API
и отклонять недопустимые опции, если контракт явно не задаёт fallback.
Замена f-string конкатенацией не устраняет уязвимость. Отчёт сканера — сигнал
анализа; проверять достижимость sink и фактическое поведение на невалидном вводе.
