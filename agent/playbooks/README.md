# Playbooks

Готовы четыре переносимые стратегии:

- `audit.md` — поиск доказуемого source-to-sink пути, формирование требуемого
  артефакта и обязательная проверка, что проект не изменён;
- `fix.md` — воспроизведение дефекта, минимальное исправление, повторный аудит,
  compile/test и контроль diff;
- `forensics.md` — inventory, корреляция независимых источников, evidence graph,
  строгий deliverable и контроль неизменности доказательств.
- `ctf.md` — чтение локальных clues/байтов, доказуемая цепочка bounded
  преобразований, точный flag-артефакт и сохранность challenge evidence.

`validation.md` задаёт общий lifecycle: baseline снимается до действий, а любой
ненулевой код финальной проверки возвращает задачу в цикл исправления.
