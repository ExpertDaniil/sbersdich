# C-13 — дополнительные CTF-задачи

## Что сделано

C-13 реализован как отдельный runtime-режим, а не как коллекция зашитых
ответов. Классификатор распознаёт CTF/flag-инструкции на русском и английском,
подключает `agent/playbooks/ctf.md` и строит контракт только по явно указанному
пути результата.

Модель получает шесть действий:

- bounded `list_files`, `read_file`, `read_bytes`, `search_text`;
- `ctf_transform` для явной цепочки преобразований;
- `write_exact_text` для финального артефакта.

`apply_patch`, `run_command`, SQL-fixer и forensics-profile в этом режиме не
выдаются. Validation policy разрешает изменение только output-файла из
контракта. Наличие непустого файла недостаточно: он должен быть создан или
изменён в текущем прогоне через успешный write action.

## Bounded CTF transform

`agent/tools/ctf.py` поддерживает base32, base64, unpadded base64url, hex, URL
percent decoding, ROT13, reverse, repeating XOR, gzip и zlib. Агент передаёт
явный список до восьми операций.

Ограничения безопасности:

- вход — не более 32768 символов;
- результат каждого шага — не более 4096 байт;
- XOR-ключ — 1–256 байт и задаётся явно как text или hex;
- gzip/zlib прекращают распаковку на лимите;
- неизвестные операции, лишние поля, плохая кодировка и неполные данные
  закрыто отклоняются;
- инструмент не читает файлы, не запускает процессы и не использует сеть.

## Локальный benchmark

`evaluation/ctf_suite.py` генерирует три независимые задачи: layered text,
binary repeating XOR и compressed Base64URL. Флаги вычисляются проверяющим
процессом и отсутствуют в instruction/workspace. Pipeline-driver знает только
input path, способ чтения, проверяемую цепочку операций и output path.

Каждая задача проходит настоящий путь:

```text
classifier → CTF contract → registry → agent loop → validator → exact verifier
```

Внутренний validator проверяет формат/границы изменений. Отдельный внешний
verifier сравнивает точные байты ответа; поэтому корректно оформленный, но
неверный флаг получает 0. Evidence хешируется до и после прогона.

## Запуск

```bash
python3 -m evaluation.ctf_suite \
  --output evaluation/results/c13_ctf.json
./agent/verify.sh
./evaluation/verify.sh
./scripts/check_all.sh
```

Ожидаемый результат suite: `C-13 CTF: 3/3 solved`.

## Что это не доказывает

Публичный репозиторий организаторов не содержит CTF-примеров, а закрытый набор
неизвестен. Поэтому 3/3 подтверждает корректность нового режима и трёх классов
преобразований, но не гарантирует балл на произвольном pwn/reverse/web/crypto
задании. Неизвестную гипотезу по-прежнему выбирает локальная LLM, а safety и
external verifier не позволяют ей выдать догадку за подтверждённое решение.

## Финальный ZIP

В submission нужны изменённые runtime-файлы из `agent/`, включая `ctf.py` и
`ctf.md`. Каталоги `evaluation/`, `docs/` и тесты используются только при
разработке и в финальный архив не обязательны.
