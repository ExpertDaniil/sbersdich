# A-01…A-03 — разбор шаблона и подключение модели

## A-01. Как запускается официальный агент

Официальная цепочка состоит из пяти шагов:

1. Harbor вызывает общую обёртку `agent.py` и передаёт ей инструкцию задачи.
2. Обёртка загружает файлы участника в `/opt/harbor/local-agent`.
3. Обёртка запускает `./run.sh "<инструкция>"` и передаёт настройки модели через
   `LOCAL_AGENT_MODEL`, `OPENAI_BASE_URL`, `OPENAI_API_KEY`.
4. `run.sh` сохраняет рабочую папку задачи и запускает Python-модуль агента.
5. Ядро выбирает действие, инструмент выполняет его, результат возвращается в
   цикл, а перед успешным завершением запускается независимая проверка.

Общая обёртка `agent.py` не копируется в итоговый архив: организаторы добавляют
и при необходимости перезаписывают её сами.

## A-02. Согласованный внутренний интерфейс

Работа товарища в C-09 уже определила общий контракт:

- `DriverContext` содержит инструкцию, выбранный режим, стратегию, ожидаемые
  артефакты, последние события и результат последней проверки;
- `ActionDriver.next_action()` возвращает ровно один `AgentAction`;
- `AgentAction` содержит имя разрешённого действия, объект аргументов и краткое
  обоснование;
- `SecurityToolRegistry` проверяет режим, аргументы и границы рабочей папки;
- `ToolResult` отделяет признак успеха, краткое описание и машинные данные;
- `finish` всегда проходит через `validate_task`, поэтому текст модели сам по
  себе не считается решением.

Новый `LocalModelActionDriver` использует этот контракт без изменения файлов
участника № 3. Это уменьшает риск конфликта при дальнейшем объединении.

## A-03. Подключение к локальной модели

`agent/core/config.py` читает и проверяет обязательные переменные. Ключ доступа
никогда не входит в безопасную сводку настроек и диагностические сообщения.

`agent/core/llm.py` вызывает совместимый адрес `/chat/completions` средствами
стандартной библиотеки Python. Это не требует установки пакетов во время
прогона. Клиент:

- ограничивает время и размер ответа;
- повторяет только ограниченное число временных сбоев;
- принимает строго один объект JSON с действием;
- не позволяет модели выбрать инструмент вне текущего режима;
- считает реальные токены из поля `usage`, а при его отсутствии хранит оценку
  отдельно;
- передаёт модели только последние события и ограниченные фрагменты стратегий.

Настройки читаются отложенно. Если известная задача решается локальным
алгоритмом, адрес модели вообще не вызывается и токены не расходуются.

Проверка настоящего адреса выполняется командой:

```sh
python3 -m agent.local_agent --probe check
```

Без настроек команда завершается понятной ошибкой и не печатает ключ. Полный
сетевой запрос можно проверить только в среде, где организатор или команда
предоставили действующий локальный адрес модели.
